## Dataset Pipeline (V2)

Scripts that build the `data/mhc_if_v2.tsv` dataset from raw IEDB exports.

### End-to-End

1. `scripts/iedb_end_to_end.py` — Runs the full IEDB-only V2 pipeline from raw export to `data/mhc_if_v2.tsv`.

### IEDB Cleaning

1. `scripts/iedb/filter_mhc_ligand.py` — Filters raw IEDB export to Class II, MS, ligand presentation, human host. Output: `data/iedb_ligand_rows_filtered.tsv`.
2. `scripts/iedb/filter_mhc_allele.py` — Keeps only valid allele rows and normalizes allele names. Output: `data/iedb_ligand_with_allele.tsv`.
3. `scripts/iedb/build_iedb_clean.py` — Builds high-resolution IEDB clean schema. Output: `data/iedb_clean_v1.tsv`.
4. `scripts/iedb/extract_low_reso_alleles.py` — Extracts low-resolution allele rows. Output: `data/iedb_low_reso.tsv`.
5. `scripts/iedb/build_iedb_low_reso_clean.py` — Builds low-resolution clean schema with `resolution`. Output: `data/iedb_low_reso_clean.tsv`.

### V2 Assembly Utilities

1. `scripts/add_positions.py` — Adds `peptide_position_info` to IEDB clean files using raw export coordinates.
2. `scripts/collect_accessions.py` — Collects protein accessions for sequence download. Outputs: `data/uniprot_accessions.txt` and related lists.
3. `scripts/identify_sources.py` — Maps accessions to source databases from raw export. Output: `data/accessions_sources.csv`.
4. `scripts/fetch_sequences.py` — Downloads UniProt FASTA sequences. Output: `data/uniprot_sequences.fasta`.
5. `scripts/fetch_ncbi_sequences.py` — Downloads NCBI FASTA sequences. Output: `data/ncbi_sequences.fasta`.
6. `scripts/regenerate_combined_fasta.py` — Merges UniProt + NCBI into `data/all_sequences.fasta`.
7. `scripts/finalize_v2.py` — Verifies positions, fixes shifts, and adds flanks. Use `--iedb-only` for IEDB-only V2. Output: `data/mhc_if_v2.tsv`.
8. `scripts/update_resolution.py` — Recomputes the `resolution` column for `data/mhc_if_v2.tsv`.
9. `scripts/validate_consistency.py` — Validates peptide vs protein slices and removes mismatches in-place.

## Epitope Head

Scripts for training, inference, ablation, and visualization of the Epitope Head model.

### Training

1. `scripts/train_v1.py` — Train Epitope Head v1 scorer (wires Modules A-G into executable training pipeline).
2. `scripts/train_v2_ablation.py` — Train Epitope Head v2 with encoder ablation for a single (encoder_id, seed) combination.

### Inference & Visualization

1. `scripts/infer_v1.py` — Run Epitope Head inference with CNN encoder on single or batched sequences; export canonical JSON payloads.
2. `scripts/visualize_demo.py` — Visualize protein residue immunogenicity risk as a heatmap HTML.

### Ablation & Diagnostics

1. `scripts/flank_ablation_test.py` — Compare original vs flank-ablated pp_AUC in ablation experiment.
2. `scripts/eval_encoder_ablation.py` — Collect metrics from completed encoder ablation runs and produce summary artifacts (ranking, mutation sensitivity, convergence, latency).

### Benchmark

1. `scripts/benchmark_head_vs_nmp.py` — Window-level comparison of epitope head vs NetMHCIIpan on a FASTA (no ground truth). Aligns predictions by (position, peptide_length), uses NMP strong-binder as label, computes per-protein AUC/AP/Recall@K/Spearman. Accelerated NMP. Outputs JSON.
2. `scripts/benchmark_iedb_test.py` — IEDB test-set benchmark: evaluates **both** head and NMP against IEDB ground-truth EL-positive spans (from `protein_samples_*.parquet` + `test_ids.txt`). Default NMP mode is "original" (batch_size=1, max_lengths_per_call=14, n_workers=1) for a clean baseline wall-time. `--metric-suite {exact,residue,iou_ladder,emd,all}` (default `all`) selects the metric families from `doc/EL_new_evaluation.md`: exact-span primary/conditional (always on), M2a residue-level AUC/AP/Pearson/Spearman over the **shared multi-k span set k∈[min_k,max_k]** (head and NMP aggregated identically — no length restriction), M6 IoU ladder with COCO-style greedy 1-to-1 assignment over configurable `--iou-thresholds` (default `1.0 0.7 0.5 0.0`; length-agnostic since IoU compares spans of differing length directly), and M3 normalized 1D EMD using the same residue aggregation. Adds `--bootstrap-n` / `--bootstrap-seed` for 95% CI and a paired Wilcoxon signed-rank (head vs NMP) on every headline metric. **Windows cache** (`--windows-cache PATH`) writes the raw `(start, k) → score` dicts for both head and NMP into a parquet (with sidecar `.meta.json` capturing allele/k-range/ckpt) after inference; `--resume-from-cache PATH` reloads the parquet and skips steps 2 (head) and 3 (NMP) entirely, so subsequent metric tweaks reuse previous inference results. For head-iteration workflows where NMP is frozen but the head checkpoint changes often, `--reuse-nmp-from-cache PATH` loads only the NMP half of the cache and skips step 3 (NMP) while running step 2 (head) fresh from `--epitope-ckpt`; cache metadata (`allele`, `min_k`/`max_k`) is validated against the current run and a mismatch fails fast (`nmp_mode` mismatch is a soft warning since NMP outputs are deterministic across modes). `--reuse-nmp-from-cache` is mutually exclusive with `--resume-from-cache` but compatible with `--windows-cache` (the rewritten cache then captures the fresh head + reused NMP, with `nmp_source: reused_from:<prev>` in the metadata for provenance). Optional `--near-miss-analysis` adds exact-vs-overlap diagnostics (`exact_ap`, `overlap_ap`, `iou50_ap`), GT exact-rank vs best-overlap-rank summaries, top-FP near/far buckets, and grouped summaries for `nmp_better`, `head_better`, and `all`. All flag families are additive and leave default benchmark behavior unchanged when omitted. Outputs JSON with per-protein + macro metrics, `statistics` block, and detailed timing.

### SLURM

1. `scripts/submit_train_v1.slurm` — Epitope Head v1 training (24hr, 1 GPU, 64GB).
2. `scripts/submit_train_v1_balanced.slurm` — Balanced Epitope Head v1 training (24hr, 1 GPU, 64GB).

5. `scripts/submit_encoder_ablation.slurm` — Encoder ablation evaluation (24hr, 1 GPU, 64GB).
6. `scripts/submit_flank_ablation.slurm` — Flank ablation experiment (12hr, 1 GPU, 64GB).
7. `scripts/submit_epitope_train.slurm` — Parameterized epitope-head training launcher (HIMP-aware, 24hr, 1 GPU, 64GB). Reads `ALLELE` (e.g. `HLA-DRB1*07:01`), `OVERRIDE_CFG` (path to a `cnn_himp_v1*.yaml` override file), `SEED`, `P_AUG` (default 0.20; set to 0.00 to disable augmentation), and optional `DATA_DIR` / `REGISTRY` / `OUTPUT_ROOT` / `PROFILE` / `PROJECT_ROOT`. Derives allele tag (`drb0701` / `drb0401` / `drb1501`) and run tag (`<cfg-basename>_<allele-tag>_seed<seed>`) automatically; constructs default DATA_DIR / REGISTRY / OUTPUT_ROOT under the cluster `work/`, `augmentation/`, and `run/` trees. Designed to replace the per-allele `submit_train_drb*.slurm` legacy scripts; a sweep loop over `ALLELE` × `OVERRIDE_CFG` × `SEED` is the canonical entry point for HIMP ablation experiments.
7. `scripts/submit_benchmark.slurm` — Head vs NMP benchmark (24hr, 1 GPU, 16 CPUs). `MODE=fasta` (default) runs `benchmark_head_vs_nmp.py`; `MODE=iedb` runs `benchmark_iedb_test.py` against IEDB ground truth. Shared overrides: `EPITOPE_CKPT`, `ALLELE`, `VARIANT_ID`, `DEVICE`. FASTA-mode: `INPUT_FASTA`, `NMP_WORKERS`, `NMP_BATCH_SIZE`. IEDB-mode: `PROFILE`, `ALLELE_SUBDIR`, `PROTEIN_SAMPLES_PARQUET`, `TEST_IDS`, `NMP_MODE`, `NMP_WORKERS`, `NMP_BATCH_SIZE`, `NMP_MAX_LENGTHS_PER_CALL`, `NMP_TIMEOUT`, `NEAR_MISS_ANALYSIS`, `WINDOWS_CACHE`, `RESUME_FROM_CACHE`, `RESULT_JSON` (pin a unique output JSON path so a config/checkpoint × split sweep does not overwrite one shared filename; default name unchanged when unset). When `NEAR_MISS_ANALYSIS=1`, the launcher appends `--near-miss-analysis` and writes to the `_near_miss.json` output variant; default behavior is unchanged when the env var is omitted or `0`. `WINDOWS_CACHE=PATH` writes the head/NMP raw `(start, k) → score` parquet (with sidecar `.meta.json`) after inference for cheap metric iteration; `RESUME_FROM_CACHE=PATH` reloads that parquet and skips head + NMP entirely so subsequent runs are sub-second on a login node; `REUSE_NMP_FROM_CACHE=PATH` loads only the NMP half and reruns head fresh from `EPITOPE_CKPT` — the workflow for head iteration on a frozen NMP. `RESUME_FROM_CACHE` and `REUSE_NMP_FROM_CACHE` are mutually exclusive (alternative read paths); `WINDOWS_CACHE` is compatible with `REUSE_NMP_FROM_CACHE` (rewrites cache with fresh head + reused NMP) but not with `RESUME_FROM_CACHE`.

## Inverse Folding — Module L: Data Selection & Evaluation (PLAN_DATA_SEL.md)

Test set curation (three-tier) and shared evaluation pipeline.

### Test Set Curation

1. `scripts/run_overlap_filter.py` — Run MMseqs2 overlap filter against CATH training sequences (L1).
2. `scripts/validate_tier1.py` — Validate Tier 1 (gold standard) candidate JSON for the IF test set (L2).
2a. `scripts/build_tier1_candidates.py` — Build a Tier 1 candidate JSON for one allele (L2 source-of-truth). Reads per-allele epitope-head test split, extracts matching EL spans from `data/mhc_if_v2.tsv`, queries PDBe SIFTS `/mappings/best_structures/{uniprot}` (endpoint: `https://www.ebi.ac.uk/pdbe/api/mappings/best_structures/{uniprot}`) for X-ray chains, applies the Tier 1 selection band (coverage 10-50%, resolution ≤ 2.5 Å, chain 100-500 AA, ≥ 2 EL spans), ranks by `epitope_coverage` (configurable), emits a validated JSON. SIFTS responses cached under `outputs/.cache/sifts/{uniprot}.json` (lazy, per-UniProt); delete a cache file to force refetch when PDB entries update. Network 404 cached as `{}` to avoid retry storms. Backed by `inverse_folding/evaluation/tier1_builder.py`.
3. `scripts/prescreen_tier2.py` — Batch pre-screen PDB candidates for Tier 2 (L3). `--selection-mode dual_scorer` (default, frozen) runs the legacy MMseqs2 overlap → epitope-head prefilter → NMP → dual-scorer gate → CATH diversity path. `--selection-mode nmp_only` runs the **Tier 2 v2** path (PLAN_DATA_SEL §12): **no epitope head** (neither prefilter nor gate) and **no structure** in selection; scores the overlap-passed pool with NetMHCIIpan at configurable peptide lengths (`--nmp-screen-lengths '15' | '12-25' | '12,15,18'`), computes `coverage_fraction` (residues covered by ≥1 strong window / length), and optionally draws a density-stratified subsample over `coverage_fraction` via `--sample {uniform,gaussian}` (`--sample-n-target`, `--sample-n-bins`, `--sample-min-per-bin`, `--sample-peak-to-tail`, `--sample-seed`). `--candidate-id-list PATH` reuses an overlap-passed protein_id list (parquet/txt) to skip MMseqs2 (overlap is allele-independent). Writes `tier2_nmp_screen_<allele>_l<lentag>.parquet` (scored) and, when sampling, `tier2_prescreened_v2_<allele>.parquet` + a `.histogram.json` sidecar. Density-stratified sampling is backed by `inverse_folding/evaluation/sampling.py`; coverage by `inverse_folding/evaluation/immunogenicity.compute_coverage_fraction`. The two-stage v2 procedure: S1 = `nmp_only --nmp-screen-lengths 15 --sample uniform` on the 75k pool → ≈5000; S2 = `nmp_only` (all lengths) on the S1 ids `--sample gaussian` → ≈3000.
4. `scripts/validate_tier3.py` — Validate Tier 3 (therapeutic) candidate JSON for the IF test set (L4).
5. `scripts/assemble_if_test_set.py` — Assemble final `test_proteins.parquet` from three tiers.
6. `scripts/download_tier2_candidates.py` — Download and filter RCSB PDB sequence database for Tier 2 candidate pool (single-chain X-ray, 100-500 AA, ≤ 2.5 Å).
7. `scripts/download_test_set_pdbs.py` — Download PDB structure files for assembled IF test set proteins.
8. `scripts/prescreen_uricases.py` — Pre-screen uricase sequences for Tier 3 via MMseqs2 overlap, epitope head prefilter, and batched NetMHCIIpan.
9. `scripts/select_tier2_v2.py` — Tier 2 v2 selection step (PLAN_DATA_SEL §12). Merges one or more NMP-only scored parquets (`--scored-glob` for the length-15 shards or `--scored-parquet` for the multi-length S2 output), de-dups by protein_id, and draws a density-stratified subsample over `--value-col` (default `coverage_fraction`) via `--mode {uniform,gaussian}` (`--n-target`, `--n-bins`, `--min-per-bin`, `--peak-to-tail`, `--mu`, `--seed`). Writes the selected subset parquet + a `.histogram.json` sidecar and prints a per-bin (available, selected) ASCII histogram. Pure CPU, deterministic, rerunnable for tuning the Gaussian before the S3 selection commits. Backed by `inverse_folding/evaluation/sampling.py`. Pairs with `prescreen_tier2.py --selection-mode nmp_only`: S1 = uniform downsample of the length-15 shards → ≈5000; S3 = Gaussian downsample of the multi-length S2 pool → ≈3000.
10. `scripts/predict_esmfold2_gt.py` — Predict structures with ESMFold2 in the dedicated `esmfold2` conda env (Biohub's top-level `esm` package shadows fair-esm, so the batch producer remains isolated). It accepts FASTA or `--from-parquet`; the parquet path deduplicates `(protein_id, sequence)` and uses the shared refold `cache_key` as the FASTA id. `--emit-fold-fasta` separates the pyarrow-dependent enumeration step from folding, and `--cache-layout DIR` normalizes every result to `<DIR>/<cache_key>.pdb + .plddt` for the benchmark dispatcher. Native mmCIF and direct/cache PDB outputs retain atom pLDDT in B-factors; the sidecar is normalized from ESMFold2's 0–1 mean pLDDT to 0–100. The JSONL manifest records `id, len, mean_plddt, ptm, sec, pass`; folding is resume-safe and shardable, and `--limit N` is the model smoke control.
11. `scripts/build_pilot_v2.py` — Build the **pilot** diagnostic subset band-aligned on `coverage_fraction`. pilot = (Tier 1 IEDB-gold anchors whose NMP `coverage_fraction` falls in the same mid-load band as Tier 2) + (Tier 2 drawn from that band with light `--n-sub-bins` stratification via `sample_uniform_bins`), to `--n-total` (default 50). Reads `coverage_fraction` (and the full canonical if_ready schema) from the `fast_v2` parquet (`--fast`) and writes a strict subset as the pilot parquet (`--output`). Tier 1 admitted iff `coverage_fraction ∈ [band_lo - tier1_band_relax, band_hi]` (only the Tier 1 **lower** edge may be widened, to catch a near-bar anchor; Tier 2 band is never relaxed); `--max-tier1 N` caps the anchor count, keeping the N highest-`coverage_fraction` ones (drops from the lower band edge up); Tier 2 fills the remainder. `--band-lo`/`--band-hi` are the Tier 2 mid-load band ([p40,p75] of canonical Tier 2 `coverage_fraction`: 0701 [0.33,0.56], 0401 [0.39,0.64]). Allele-specific, deterministic (`--seed`), pure CPU. Backed by `inverse_folding/evaluation/sampling.py`. Note: `fast_v2` is the source pool, so pilot Tier 2 ⊂ fast Tier 2 by construction.
12. `scripts/build_highrisk_demo.py` — Select a high-risk subset by a **PRIMARY baseline's NMP + epitope-head burden**. Two goals → two SEPARATE sets (the ProteinMPNN and DPLM-native high-burden tails barely overlap — full-range Spearman ~0.46, top-decile ~0.11, top-150 share ~31/150 — so they must not be merged): demonstration / "best effect" uses `--primary-imm-dir` = ProteinMPNN (beat the reported baseline); RF validation / iteration uses `--primary-imm-dir` = DPLM-native (RF acts on DPLM, needs real headroom). Selection (default `--rank-mode both_nmp_head`) ranks by `min(nmp_pct, head_pct)` over the canonical set and takes top `--n-target` — proteins whose NMP strong_frac (`n_strong_binders/n_windows_scored`, median over designs) AND head `global_risk` (median) are BOTH high. NMP is the non-circular primary validator; the head is promoted from a gate to a **co-ranking axis** (ACCEPTED circular — head is the RF guidance — but it correlates with NMP ~0.6, so it sharpens rather than distorts). `--rank-mode nmp` ranks by NMP only. Structure is NOT gated. `--diag-imm-dir LABEL=DIR` (repeatable) attaches cross-baseline `<LABEL>_nmp`/`<LABEL>_head` columns so each set records where it sits under every baseline. Reads `imm_nmp.parquet`+`imm_head.parquet` per dir; writes a canonical IF-ready subset (`--canonical-if-ready`) + `sel_nmp/sel_head/both_min_pct/highrisk_rank` + diag columns. Outputs e.g. `highrisk_pmpnn_demo_v1_<tag>.parquet` (primary=ProteinMPNN) and `highrisk_dplm_iter_v1_<tag>.parquet` (primary=DPLM-native).
13. `scripts/build_pilot_difficulty.py` — Build the **pilot-v3** diagnostic subset stratified UNIFORMLY across de-immunization difficulty on the unguided **NoD** baseline (vs `build_pilot_v2.py`'s `coverage_fraction` band, which is generator-independent but difficulty-blind). Difficulty = median NMP `strong_frac` (`n_strong_binders/n_windows_scored`) over `--half-a-designs` (**default: all 8** NoD designs → cleanest per-protein estimate). Difficulty axis is **NMP-only** (non-circular; the epitope head is the RF guidance, recorded as `pilot_head_halfA` diagnostic but never defining the axis). Places candidates in equal-frequency quantile bins (`--n-bins`) and samples uniformly per bin to `--n-total` (remainder → hardest bins). **Optional regression-decoupling** — the highrisk selection bias (binning on the same NoD realization later used as the eval baseline) is severe only for *extreme-tail* selection + a quantitative small-effect claim, so it is a second-order effect for a UNIFORM iteration set and binning-on-all-8 is the default; for a rigorous quantitative per-bin method-vs-NoD number, reserve a disjoint `--half-b-designs` (its burden is recorded as `pilot_baseline_nmp_halfB` and did not drive selection) or regenerate a fresh NoD baseline for the ~50 proteins at eval time. Reads the merged NoD imm dir (`imm_nmp.parquet`+`imm_head.parquet`, `design_idx` 0-7) via `--nod-imm-dir`; writes a subset of `--canonical-if-ready` (main IF-ready) + `pilot_difficulty_nmp/_pct/_bin`, `pilot_head_halfA`, `pilot_difficulty_designs`/`pilot_baseline_designs` (+ `pilot_baseline_nmp_halfB` when a half-B is reserved), plus an optional `--fasta-output`. Allele-specific, deterministic (`--seed`), `--min-coverage` matches canonical (0.8). Note: pilot_v2 (coverage-band) is retained in parallel — it is the cohort of the SC-GR planner (`PLAN_PLANNER_SC_GR.md`); pilot_v3 is the new difficulty-uniform iteration set.

### SLURM

1. `scripts/submit_assemble_test_set.slurm` — Assemble final IF test set (8hr, 1 GPU, 64GB).
2. `scripts/submit_prescreen_tier2.slurm` — Tier 2 prescreening pipeline. `MODE=dual_scorer` (default) runs the legacy GPU path. `MODE=nmp_only` runs the Tier 2 v2 NMP-only screen (PLAN_DATA_SEL §12) — **pure CPU, no GPU**; submit CPU-only, e.g. `MODE=nmp_only NMP_WORKERS=48 NMP_SCREEN_LENGTHS=15 SAMPLE=none ALLELE="HLA-DRB1*07:01" sbatch --partition=cpu --qos=short --gres=none --cpus-per-task=48 --time=12:00:00 scripts/submit_prescreen_tier2.slurm`. Env: `MODE`, `NMP_WORKERS`, `NMP_BATCH_SIZE`, `NMP_SCREEN_LENGTHS`, `CANDIDATE_ID_LIST` (defaults to `_prescreen_head_results_<allele>.parquet`), `SAMPLE`, `SAMPLE_N_TARGET`, `SAMPLE_N_BINS`, `SAMPLE_MIN_PER_BIN`, `SAMPLE_PEAK_TO_TAIL`, `SAMPLE_SEED`, `N_SHARDS`, `ALLELE`. For the S1 75k scan, submit as a **job array** with small shards (fast backfill, parallel): `N_SHARDS=16 ... sbatch --array=0-15 --partition=cpu --qos=short --gres=none --cpus-per-task=8 --mem=16G --time=3:00:00 ...` — each task scores `sorted(pool)[task_id::N_SHARDS]` → `tier2_nmp_screen_<allele>_l15.shardNNof16.parquet`; concat the shard parquets before S1 sampling.
3. `scripts/submit_download_tier2.slurm` — Download Tier 2 PDB candidate sequences (2hr, CPU, 16GB).
4. `scripts/submit_prescreen_uricases.slurm` — Uricase pre-screening for Tier 3 (24hr, 1 GPU, 64GB). Parameterized: `ALLELE`, `EPITOPE_CKPT`.
5. `scripts/submit_esmfold2_gt.slurm` — ESMFold2 batch/cache precompute (2hr, 1 GPU, 64GB; arrays supported). Activates `esmfold2`, runs offline from `HF_HOME`, and forwards fold-quality knobs. Set `FROM_PARQUET=<generated.parquet>` to emit a cache-key FASTA in an `immune-design` subshell and fold it in the ESMFold2 env; `CACHE_LAYOUT` defaults to `${OUT_DIR}/cache` in this mode, producing the canonical cache consumed by `evaluate_phase_c.py --refold-model esmfold2`.

## Inverse Folding — Phase B: Experiment Preparation (PLAN_IF.md)

Mechanical preparation jobs that bridge the fixed IF test set and Phase C reference-flow experiments.

### h-map Precompute

1. `scripts/build_if_ready_test_set.py` — B1.5 structure/sequence cleaning gate for Phase C. Reads the assembled biological-sequence test-set parquet plus downloaded PDB/mmCIF structures, extracts resolved single-chain backbone residues, canonicalizes modified amino acids via BioPython's extended PDB residue map, collapses duplicate author residue IDs and alternate conformers, writes cleaned single-chain PDB/mmCIF structures plus an IF-ready parquet whose `sequence`/`sequence_length`/`if_chain_id` exactly match DPLM `load_coords()` output. Original biological sequence, original length, source structure path, residue-number mapping, and failure ledgers are retained for audit.
2. `scripts/precompute_h_maps.py` — Shared B2/B3 CLI that computes wide per-protein h-map parquets from epitope-head `debug.h_raw` and `residue_hotspot`, with metadata sidecars, resume support, failure ledgers, and CATH corpus stats for JSONL training inputs. Its `allele_tag()` (used for the metadata `run_id`) delegates to `reference_flow.runtime.safe_allele_tag` with HLA-prefix normalization → the unified file-safe tag `HLA-DRB1_07_01` (matches `submit_precompute_h_test/cath.slurm` which now write `h_maps_HLA-DRB1_*.parquet`). The on-disk filename is set by `--output-parquet`/`--output-meta` from the SLURM producer, not by this module.

### Evaluation Integration

1. `scripts/evaluate_phase_c.py` — B4 end-to-end evaluator for Phase C outputs. Reads `generated.parquet` plus the test-set parquet and writes `imm_head.parquet`, `imm_nmp.parquet`, canonical v2 `structural.parquet`, and canonical v2 `structural_residues.parquet`; mode-switchable (`imm|struct|all`) and idempotent per mode. Structure defaults to the cache-read `esmfold2` backend and requires `--refold-cache-dir`; `esmfold`, `protenix`, and `af3` remain explicit alternatives. The summary retains scTM and exactly one global full-trace C-alpha RMSD, then reports predicted/reference pLDDT and all active-site geometry through exact all-heavy-side-chain correspondence after that global alignment. The residue table stores index-addressable atom counts, squared-error sums, per-residue side-chain RMSD/max displacement, pLDDT, and match/completeness status. Any later index subset is exactly aggregatable as `sqrt(sum(sidechain_sq_error_sum) / sum(sidechain_atom_count))`; identity or atom-set mismatch fails closed. `--structural-metrics-v2` is a deprecated accepted no-op because v2 is now canonical. Lightweight reuse lives in `inverse_folding/evaluation/structural_metrics_v2.py` (stdlib-only import, lazy NumPy, cached reference context, selective metric families). `--imm-full` independently emits the long immune tables.
2. `scripts/build_wt_facade.py` — Build a WT `generated.parquet` facade (`protein_id`, `design_idx`=0, `sequence`) from a canonical IF-ready test parquet so the WT test set can be scored by `evaluate_phase_c.py` as a single-design generation (the WT immune baseline). ### RF Refinement (PLAN_RF_REFINE.md)

Post-hoc targeted epitope-core elimination: a stage between generation and evaluation that mutates a best-of-N RF design's residual high-risk positions to drive the distinct NMP strong-core count toward 0 while preserving fold and freezing active-site anchors. Pure search logic lives in `inverse_folding/reference_flow/refine.py` (core extraction, hotspot blocks, editable positions, block-structured enumeration, `rank_margin_mass`, `structure_gate`, `accept_refinement`, `refine_sequence` beam search — all oracle-injected, no torch/IO).

1. `scripts/refine_rf_designs.py` — refinement driver. Seeds come from `--seed-table` or the flexible `--run-dir` layouts, hard anchors are frozen from `--constraint-manifest`, and output-gated beam search refolds only count-dropping candidates. Standard runs use one persistent isolated ESMFold2 worker (`--refold-model esmfold2_live`) and the protocol gate `scTM >= X AND cat_max_scRMSD <= Y AND predicted_active_site_min_pLDDT >= Z`; all three thresholds are required CLI inputs with no numeric defaults. `cat_max_scRMSD` is the worst all-heavy-side-chain RMSD over the manifest's direct-functional catalytic subset (v0 manifests explicitly map hard anchors to that set); missing catalytic provenance or incomplete geometry fails closed. `--structure-gate-profile legacy` retains the old seed-relative/whole-anchor gates only for explicit compatibility runs. The post-search full-metrics pass reads the same normalized ESMFold2 cache and always writes canonical v2 `refined/structural.parquet` plus index-addressable `refined/structural_residues.parquet`. Immune output semantics and NMP batching are unchanged.

   `--structural-metrics-v2` remains accepted as a deprecated no-op for old launch commands; v2 is unconditional and canonical.

2. `scripts/submit_refine.slurm` — ailab (H200, 8 cores/GPU) launcher for the refine driver: one GPU job runs all three oracles (immune head + persistent ESMFold2 worker on the GPU, NetMHCIIpan on the 8 CPU cores with `NMP_WORKERS` defaulting to `--cpus-per-task=8`). Standard mode defaults `REFOLD_MODEL=esmfold2_live`, resolves the isolated Biohub package overlay from `ESMFOLD2_ENV`, and requires the caller to set `GATE_SCTM_MIN`, `GATE_CAT_MAX_SCRMSD_MAX`, and `GATE_ACTIVE_SITE_MIN_PLDDT_MIN`; the launcher contains no protocol threshold values. Other model/search/full-metrics controls remain environment-parameterized, and each shard emits `imm_head`/`imm_nmp`/`structural`/`structural_residues`. `STRUCTURE_GATE_PROFILE=legacy` is the explicit compatibility path. PLI H100 fallback: `sbatch --account=pli_x --qos=pli-low --partition=pli --constraint= scripts/submit_refine.slurm`.

   The launcher defaults `REFINEMENT_STRUCTURE_METRICS=global_ca_rmsd,plddt,sidechain`; protocol-gate calibration values belong in each run invocation/artifact, not this registry. `merge_refine_shards.py` consumes the canonical v2 tables directly and joins their summary fields into `master.parquet`.
3. `scripts/merge_refine_shards.py` — consolidate a sharded refine run's per-shard `shardKKofNN/refined/` outputs into `<run>/merged/`. Sharding is at the SEED level, so a protein's seeds can span shards and each shard restarts `design_idx` at 0 → the raw `(protein_id, design_idx)` key COLLIDES across shards; the merger adds a `shard_idx` column + a globally-unique `design_uid` (`s{shard:02d}_{protein_id}_d{design_idx:04d}`) to every per-design table so concatenation and joins are collision-safe (validated against char24_0701: 5025 raw-key collisions, 0 `design_uid` collisions). Concatenates `refined_designs`/`imm_head`/`imm_nmp`/`structural`/`structural_residues` (+`imm_head_residues`/`imm_nmp_peptides` if present) + `refine_trace`, builds `master.parquet` (one row per design: search objective `core_count_before/after`/`n_mutations`/`muts`/`scTM_after` + cumulative `true_muts` left-joined to the evaluate-schema structural + `imm_nmp` + `imm_head` metrics on `design_uid`), selects `best_count0_per_seed.{parquet,fasta}` (the min-edit / max-scTM distinct-core==0 variant per input seed = the definitive de-immunized set), and writes `merge_summary.json` (reach-0 stats + `final_metrics_status` roll-up). `--top-k K` additionally emits `top{K}_per_seed.{parquet,fasta}` (the K lowest-`core_count_after` variants per seed, NOT requiring 0 — the deliverable for ceiling probes where 0 is not guaranteed). `--dplm-native-structural <structural.parquet>` adds `dplm_native_scTM` (per-protein median scTM) + `delta_scTM = scTM − dplm_native_scTM` to `master` (fold quality relative to the DPLM base, for proteins whose base folds poorly in absolute terms). Usage: `python scripts/merge_refine_shards.py --run-dir <array-run-dir> [--top-k 4 --dplm-native-structural <file>]`.

### RF-Refine Fusion (PLAN_RF_REFINE_FUSION.md)

Head-guided, structure-constrained edit-and-repair reference flow (supersedes the deferred "Unified Architecture" in `PLAN_RF_REFINE.md` §11). Runtime immune signal is **Head-only** — NetMHCIIpan has no role and is never imported (`FusionOracles(head_fn, struct_fn)` has no `nmp_fn`). Pure, oracle-injected logic lives in `inverse_folding/reference_flow/fusion/` (`state`/`config`/`objective`/`moves`/`oracles`/`runner`/`selection`/`structure_metrics` — all torch-free; the parent `reference_flow/__init__` is lazy so importing them pulls no torch).

1. `scripts/run_rf_refine_fusion.py` — Fusion driver. Reads complete RF designs, builds an N-slot feasible initial population, runs greedy/beam/FK complete-state selection with per-protein atomic resume, and writes candidate/particle/lineage/elite/evaluator artifacts. The current presets use `structure.backend: esmfold2_live` and `active_site_metric: sidechain_max_anchor`. `inverse_folding/evaluation/esmfold2_live.py` starts one persistent worker with the current `immune-design` Python and Torch, then overlays Biohub's `esm`/`transformers` code from `--esmfold2-site-packages` only inside that worker. This avoids replacing fair-esm in the Fusion/DPLM process and avoids reloading ESMFold2 per candidate. Every result is normalized into the shared refold cache with atom pLDDT retained. Fusion computes scTM, one global C-alpha RMSD, global/active-site pLDDT, and exact all-heavy-side-chain active-site metrics; incomplete correspondence fails closed. `rf_refine_fusion_esmfold2_probe.yaml` bounds a real integration probe to one initial fold plus at most one round-1 fold. NetMHCIIpan remains absent. **§2.11 additive audit seam (V1)**: round-0 admission now RECORDS every facade row it examines — admitted (with `slot_idx` + `particle_id`) or rejected (with the reason: `non_canonical_sequence` / `length_mismatch` / `anchor_mismatch` / the definitive gate reason plus scTM/pLDDT) — into `fusion_initial_admission_verdicts.parquet`, and counts the definitive round-0 folds into `manifest.initial_refolds_by_protein`. The decisions are unchanged (§2.11 authorizes recording, not behaviour change); what changed is that they stop vanishing. This is the ONLY place the definitive verdict on a facade row exists, because the V1 entry stage defers structure — an anchor violation on a completed sequence is detectable nowhere else, and the round-0 refold spend was previously charged in no artifact at all, so a matched-compute check on refolds compared two zeros. `entry_source_id` travels from the facade onto `ParticleState`, is inherited by every descendant, and is persisted in `fusion_particles`, `fusion_elite` (as `entry_source_id` + `initial_entry_source_id`) and the verdict table, so the elite names its facade row without a sequence join; it is also part of `_seed_digest`, since two entry runs whose ranked sequences converge but whose roots differ would otherwise share a v0 resume key and inherit the wrong lineage. Tested: `tests/scripts/test_rf_fusion_v1_admission_audit.py`.

2. `scripts/submit_refine.slurm` `MODE=fusion` — branches the existing launcher to the Head-only Fusion driver. It derives the Biohub package path from `ESMFOLD2_ENV` (or accepts `ESMFOLD2_SITE_PACKAGES`) and passes `ESMFOLD2_MODEL`, loop/step/sample/seed controls, plus `REFOLD_CACHE_DIR`; the actual worker executable remains the active `immune-design` Python. The static CPU request is NMP-sized, so Fusion should normally override it to 2 cores.

#### v1 entry (pre-terminal continuation-value allocation, `PLAN_RF_REFINE_FUSION_V1.md`)

The v1 entry replaces the "sample-N-then-admit" initial population with a partial-root continuation-value allocation: estimate each pre-terminal root's value by K_EST complete rollouts, rank roots deterministically, materialize a fresh `final` completion per ranked root, and feed the ordered facade into the **unchanged** v0 Fusion admission. Pure, torch/pandas/Head-free logic lives in `inverse_folding/reference_flow/fusion/v1_*` (`v1_records`/`v1_config`/`v1_seeds`/`v1_alloc`/`v1_admission`/`v1_ledger`); the sampler-side pre-denoiser checkpoint / exact replay / fork / resumed batch lanes live in `inverse_folding/reference_flow/sampler.py`. **Null-runtime isolation is verified at the SAMPLER**, not just in the config: `tests/inverse_folding/test_reference_flow_v1_null_isolation.py` feeds the sampler wildly different h vectors under `constant_one` and requires byte-identical trajectories, with a POSITIVE CONTROL that runs the same comparison under `linear_clamp` and requires divergence (so a trivially-passing isolation test cannot masquerade as evidence), plus a tripwire controller proving `controller=None` is a real absence rather than a dead branch. The scripts below are the IO + orchestration layer (they may import pandas; the pure package must not). The production CLI driver (`run_rf_fusion_v1_entry.py`) and launcher (`submit_if_phase_c.slurm MODE=v1_entry`) are wired for BOTH P1 arms AND for T0 (`phase: t0`, dispatched on the config's phase).

**V1-A scope (the only variant implemented).** P1 has exactly TWO arms — `preterminal` (continuation-value allocation at a frozen ρ_edit<1; `build_preterminal_facade` orders by ROOT VALUE, never by the materialized terminal Head) and `terminal` (independent complete `c1_null` trajectories; `build_terminal_facade` orders by exact terminal Head and submits only the top frozen common `F_cap`, and a pool smaller than that cap is a hard failure because `M_T < F_cap` can only be a DFE accounting error, §3.2.1). T0 has exactly THREE policy views — `selected_partial`, `random_partial`, `independent_full` — where selected/random are MEMBERSHIP views (`select_random_membership`, seeded only by `SeedContext.random_membership_seed()`) over ONE shared root pool and ONE shared held-out `K_EVAL` table, so a policy label never opens its own continuation stream; T0's structure budget is `t0_reserved_structure_requests(q) = 3·Q_T0`. Branch-and-materialize is **removed**, not merely unused: `authorize_final_materialization` accepts only a fresh `final` continuation of a SELECTED root, making reuse of an estimator endpoint as a parent structurally impossible. The whole entry runtime is the frozen null kernel (`g(h)=1`, `controller=None`, no h-map, §2.12).

3. `scripts/rf_fusion_v1_artifacts.py` — V1 entry artifact writers (PLAN §5). Frozen `V1_TABLE_SCHEMAS` for the 15 §5.1 parquet tables (stable columns even when empty, explicit order, canonical sort on write, hard error on any undeclared column via `write_stable_parquet`), content-addressed snapshot-payload sidecars (`write_payload_sidecar`/`read_payload_sidecar`, integrity-verified before reuse), `cost_ledger.jsonl` + `manifest.json` writers, and row builders (`partial_root_row`/`continuation_rows`/`root_value_rows`/`facade_rows`/`admission_rows`/`coverage_rows`) that map the pure dataclasses to their table rows. `continuations` never deduplicates distinct logical seeds. Tested: `tests/scripts/test_rf_fusion_v1_artifacts.py`.

4. `scripts/rf_fusion_v1_entry_core.py` — per-protein PRE-TERMINAL entry orchestration (PLAN §2.9-§2.11, §3.3). `run_entry_protein(...)` wires root prefix → estimator value (`root_value`) → deterministic value beam (`select_value_beam`) → fresh `final` materialization → root-value-ordered facade (`build_preterminal_facade`) → admission audit (`admit_facade`), returning the full replay-graph records plus an event-level cost ledger. **Honest structure deferral (§2.11)**: the V1-A entry stage does not run definitive structure, so a deferred gate yields `verdict="deferred_to_v0"`, `structure_feasible=NULL` (never False), no `slot_idx`, a `deferred` ledger event charging `structure_requests=0` (v0 charges it when it actually folds), and the protein status `entry_complete_structure_deferred` — never `terminal_success`. `admit_facade` refuses to mix evaluated and deferred rows, which would make `n_admitted` a partial count that reads as a complete one; `ENTRY_OK_STATUSES` in the cohort layer likewise counts only proteins that produced a usable entry, so `entry_insufficient_unique_roots` (which returns a result rather than raising) can no longer inflate `n_proteins_ok` and the driver's exit code. The facade offers the top `initial_refold_attempt_cap` roots (not just top-N) so a rank-0 structure failure falls back to a lower-ranked root; facade order always follows root value, never the materialized terminal Head. Model surfaces (root generator / completer / Head / structure gate / trajectory generator) are injected via `EntryOracles` so the graph is testable without models. Torch/pandas-free. **`run_t0_protein(...)`** runs one T0 maturity point: root prefix → estimator value → ONE common held-out `K_EVAL` table → three policy VIEWS (`selected_partial` = the value beam, `random_partial` = a Head-INDEPENDENT membership draw from the SAME pool via `SeedContext.random_membership_seed()`, `independent_full` = the compute-matched full-trajectory control) → an equal-sized Head-independent `Q_T0` subsample per view (`3·Q_T0` structure requests). `eval_membership_view` hands back the very tuples from the shared table, so switching a policy label cannot redraw a continuation — if it could, T0 would measure sampling noise instead of selection. T0 materializes NO parent (no `final`, no admission): building one would spend the P1 budget and let a calibration outcome leak into the P1 population — its only structure spend is the `3·Q_T0` subsample, each request recorded honestly (a deferral is `deferred_to_v0`, never a pass). **Each grid point is its own matched root-attempt group** (PLAN §2.3:238-241 — "A T0 grid runs separate matched root-attempt groups, so prefix compute is not amortized across maturities"): the point APPENDS to the shared journal (so a crash mid-grid still preserves every paid attempt) but READS only the tail it wrote. Aliasing the journal's lists instead let a later maturity pass its own coverage gate on an EARLIER maturity's roots and inflated its reserved budget — hence the size of the compute-matched control it is judged against — producing real-looking wrong numbers with no error anywhere. `full_control` ledger ids carry `rho_id` for the same reason: two points sharing a logical event id silently deduplicate one point's control cost out of the matched-compute total. The `independent_full` control is **Head-ranked under the Terminal law** (the same `head_risk_by_md5` firewall and the same `(risk, md5, source_id)` total order the Terminal arm uses); without a Head value it carries no quantity comparable to the partial views and runbook §6.1 condition 3 is unanswerable. `_scored_set` tail-validates every completion, matching the control it is compared against. A point whose `3·Q_T0` requests were ALL deferred returns `t0_structure_deferred`, which is NOT in `ENTRY_OK_STATUSES` — reporting `t0_complete` there would exit 0 on a calibration that cannot answer its own condition 3. The cohort runner dispatches on `phase == "t0"`, runs the whole `rho_grid` into ONE checkpoint per protein (a partially written grid is not a usable calibration), and writes the three `t0_*` tables **plus the standard §9 evidence tables** (`root_attempts` / `partial_roots` / `maturity_telemetry` / `continuations` / `root_values` / `root_selection` / `complete_entry_pool`, namespaced by `rho_id`), the per-maturity `reserved_dfe_by_rho`, and every realized seed. Membership tables alone made all four runbook §6.1 GO/KILL conditions uncomputable from disk while the run exited 0. Every membership row carries the FULL three-policy membership plus `common_eval_provenance` — the shared-table continuation id — so a reviewer reading the parquet can SEE that selected and random point at the same evidence instead of having to trust it. Canary: `rf_fusion_v1_entry_canary_t0.yaml`. **`run_terminal_protein(...)`** orchestrates the other P1 arm (§3.2.1): `M_T` independent complete `c1_null` trajectories → exact terminal Head via the SHARED `head_risk_by_md5` firewall → `build_terminal_facade` (Head rank, top `F_cap`) → the same v0 admission. It exists because v0's `build_initial_population` deliberately does **not** preselect on Head (its `design_idx` is whatever order generation emitted), while the pre-terminal facade is ordered by root value — an arbitrarily-ordered Terminal facade would confound "does Head selection help" with "does selecting at a partial state beat selecting at the endpoint", and V1-A isolates the latter. Every generated trajectory is charged full DFE in the `terminal_complete` ledger phase, including failures and the ones ranking below `F_cap`, because that compute came out of the matched budget. Tested: `tests/scripts/test_rf_fusion_v1_entry_core.py`, `tests/scripts/test_rf_fusion_v1_terminal_arm.py`.

5. `scripts/rf_fusion_v1_cohort.py` — cohort runner + aggregation (PLAN §4.2, §5, §3.3). `run_entry_shard(...)` runs a subset of the requested cohort, writing one atomic per-`(protein, arm)` checkpoint whose `run_sig` binds the resolved config digest (shared source: `rf_fusion_v1_preflight.entry_config_digest`) and the protein's §4.2 input signature (a matching checkpoint is reused, a changed/cross-arm one re-runs). **Retry durability (§3.3)**: a FAILED checkpoint under the same resume identity is not discarded on resume — its ledger is carried forward and the retry runs in the next `attempt_epoch`, whose `attempt_id`s are suffixed `#e<n>`. Physical cost therefore SUMS across a crash (the GPU time was really spent) while logical method cost stays counted once per `event_id` (one root attempt is one unit of method cost however many times it had to be executed), so a run that crashed does not report a different DFE than one that did not. `aggregate_entry_artifacts(...)` reads the frozen requested cohort's checkpoints under the current arm, re-verifies each checkpoint's resume identity (config digest + optional `input_signature_by_protein`) and unique join keys, and emits the §5 family with canonical shard/order-independent ordering, a coverage row for every requested protein (missing ones surfaced via `build_cohort_coverage`), a single-counted cost ledger, and a manifest. **`facade_collapse.parquet`** records every facade lineage dropped by sequence convergence with the representative that absorbed it: PLAN §2.11:489-501 requires an unbroken root → continuation → facade → admission chain and §5.3:828 makes a missing edge invalidate the run, so a collapsed row must not simply vanish after reading `selected=True, fresh_materialization_authorized=True` in `root_selection`. `complete_entry_pool.collapsed_into_source_id` says WHY `rank` is null — non-null means it ranked INSIDE `F_cap` but converged, null means it genuinely ranked below the cap; without it a top-ranked trajectory read as "generated but not submitted". The manifest carries `reserved_dfe_by_protein` for both arms (T0's is the sum over its grid, broken out in `reserved_dfe_by_rho`) so the reserved side of the matched-compute audit reaches disk. `_realized_seeds` enumerates a `final:` seed only for the RANKED beam — the unique-root pool is a minimum coverage requirement and is normally larger, so one-per-unique-root claimed draws that never happened. Tested: `tests/scripts/test_rf_fusion_v1_cohort.py`, `tests/scripts/test_rf_fusion_v1_t0_grid.py`, `tests/scripts/test_rf_fusion_v1_facade_lineage.py`, `tests/scripts/test_rf_fusion_v1_seed_provenance.py`.

6. `scripts/rf_fusion_v1_preflight.py` — V1F6 model-free preflight / print-config (PLAN §3.4, §4.1-4.2). Torch/pandas/Head-free: `resolve_entry_config` (fail-fast `V1EntryConfig`), `entry_config_digest` (the single shared config-digest source used by the cohort `run_sig`), `project_budget` (worst-case §3.4 DFE + reserved-refold-cap `F_cap + N·R_parent·n_rounds`), which dispatches per phase/arm through ONE shared cap+walltime assembly so the reported total and the pass/fail verdict can never disagree. **The T0 projection carries two multipliers that each, if dropped, turn the §3.4 gate into a no-op** (the projection is the only place `max_dfe`/`max_refolds` are ever checked): every per-protein term scales with `len(rho_grid)` (one shard runs the WHOLE grid), and the compute-matched `independent_full` control is real spend on top of prefix/est/eval (`dfe_full_control`, reported as its own term — `dfe_final` stays 0 because T0 materializes no parent, and a non-zero value there would say it does), `terminal_trajectory_count(reserved_dfe_per_protein, s_steps, facade_cap)` = `floor(C_reserved / S)` with a HARD failure on `M_T < F_cap` (a DFE accounting/off-by-one error, never a reason to shrink the Terminal facade), `project_budget(..., reserved_dfe_per_protein=...)` for the Terminal arm (which must be handed the persisted pre-terminal reservation; the pre-terminal arm refuses to be handed one, since it produces it) and `project_budget(..., reserved_dfe_by_protein={...})` for a Terminal COHORT, whose total is the SUM of the per-protein reservations — `min × n_proteins` under-reports the moment the proteins differ, while `min` remains what the per-protein `M_T ≥ F_cap` invariant is tested at. `render_print_config(..., budget=...)` takes the already-projected budget, so `--print-config` resolves for the Terminal arm too (it previously re-projected without `C_reserved` and hard-errored — leaving `V1_SUBMODE=print_config`, the one pre-launch audit an operator has, unusable for the arm whose budget most needs auditing), `assert_launch_feasible` (fail-closed launch gate; an unverifiable walltime is a hard failure), `seed_stream_summary`, `render_print_config`, and `assert_null_entry_kernel(args, config)` — the **null-runtime firewall** (§2.12): reads the entry sampler YAML as a raw mapping (deliberately not through the typed loader, so an unrecognized `controller:` section is still visible), requires `amplification.form == constant_one`, refuses `h_shuffle.enabled`, refuses any `h_map`/`controller_config`/`h_corpus_stats` argument and any config declaring `controller_enabled`/`h_maps_present`, and returns a `NullKernelReport` whose `rf_sampler_digest` binds the kernel identity to the file's CONTENT (the config's `entry_rf_config` is only a label). Model-free, so it refuses before torch is imported on both the dry-run and the real launch path. Tested: `tests/scripts/test_rf_fusion_v1_preflight.py`, `tests/scripts/test_rf_fusion_v1_null_firewall.py`.

8. `scripts/rf_fusion_v1_oracles.py` — V1F6 Phase B real Arm-C oracle wiring (torch; imported lazily by the driver). Behavior is validated on the cluster canary (V1F7); tested locally: `tests/scripts/test_rf_fusion_v1_oracles.py` (the pure transforms). `trajectory_generator` is the TERMINAL arm's seam: one independent complete `c1_null` trajectory per call (no continuation request, no checkpoint), charging exactly S whether it succeeds or fails. Labeled canary configs: `rf_fusion_v1_entry_canary.yaml` / `rf_fusion_v1_entry_canary_terminal.yaml` (deployment smoke only, not production).

7. `scripts/run_rf_fusion_v1_entry.py` — V1F6 production entry driver (Arm-C P1; Head-only, **no NMP**). Model-free control plane: `--entry-config`/`--terminal-repair-config`/`--rf-sampler-config` are separate required identities (§2.12) — the entry kernel must be NAMED and is verified by `assert_null_entry_kernel` before anything imports torch, on both the dry-run and the real path; `assert_no_position_dependent_flags` refuses `--h-map`/`--h-maps-parquet`/`--controller-config`/`--h-corpus-stats` at the CLI boundary with exit 2 and a named reason, and the provenance has no `h_map_parquet` key at all (a null-valued key would still imply the concept is in scope). `--window-k-min`/`--window-k-max`/`--head-window-batch-size` are real method knobs bound into the resume identity. `--print-config` and a strict `--dry-run` resolve without loading a model, `build_content_provenance` computes the §4.2 CONTENT digests of every input file + config/schema/commit/CLI identities and `input_signature_from_provenance` binds resume to them. **Fail-closed launch gate (§3.4)** — every check runs on ALL paths (including `--print-config`), on a login node: `_REQUIRED_FILE_ARGS` (entry/terminal/sampler configs, test set, DPLM + Head checkpoints) must exist and be readable — an absent path is a FAILED launch, never a null digest; `_REQUIRED_DIR_ARGS` validates `--head-config-dir` (bound by `directory_content_digest`, so an in-place `model.yaml` edit rebinds resume) and `--pdb-root`; `load_cohort_rows` validates the test set's `{protein_id, sequence, sequence_length}` columns, exactly one row per requested protein, `len(sequence) == sequence_length`, an AA20-only reference sequence, and a resolvable backbone (via the torch-free `inverse_folding/reference_flow/structure_paths.py`, the SAME resolver the run uses), then `cohort_structure_digest` binds the specific structures the cohort resolves to; `validate_hard_anchors` loads `--constraint-manifest` and runs `validate_against_sequence` per protein (an out-of-range index or an anchor naming a protein outside the cohort raises). **Exit codes**: `EXIT_OK=0` only when the whole requested cohort succeeded, `EXIT_FAILED=2` when nothing usable was produced, `EXIT_PARTIAL=3` otherwise unless `--allow-partial-cohort` (a partial cohort is a different, outcome-correlated cohort). `write_facade_generated_parquet` refuses a zero-row facade (v0 would read an empty parquet as its initial population and report a clean run over nothing) AND a duplicate sequence within a protein, and additionally emits `fusion_initial_admission.parquet` — the **entry→v0 join table**. v0 builds particle ids as `{protein}:r0:s{slot}:{sequence_md5[:12]}`, so on its own the entry→v0 attribution closes only on the sequence — and PLAN §2.11:531 says plainly "Do not reconstruct the mapping from sequence alone. Distinct roots may converge to the same complete sequence." Two things fix that. (1) The generated parquet carries an explicit **`entry_source_id`** column; `build_initial_population` puts it on the round-0 `ParticleState`, every descendant inherits it, and `fusion_particles.parquet` persists it — so a terminal elite NAMES its facade row instead of requiring an md5 join. (2) `collapse_facade_by_sequence` still collapses convergent rows to the best-ranked representative (re-densifying `design_idx`) — for ONE reason: two identical round-0 particles would hold two of v0's N slots and draw twice the child budget for one basin, defeating v0's own rule that multiplicity must not buy ancestry mass. (It costs no extra refold — the structure cache keys on `sequence_md5` — and attribution would still be exact, since `particle_id` embeds `slot_idx`; both of those were previously given as reasons here and were wrong.) The dropped lineages are now PERSISTED to `facade_collapse.parquet` rather than living only on the in-memory result. A collapse that shortens the facade below `F_cap` returns the distinct status `entry_facade_collapsed` (excluded from `ENTRY_OK_STATUSES`), because it under-delivers against the matched initial-refold budget; below `N` the entry stage hard-fails rather than letting v0 report the shortfall as a terminal-stage failure. `main(argv, *, oracles_factory=None, length_resolver=None)` builds the real Arm-C oracles lazily behind `oracles_factory` (torch only loads there) so the whole driver is fake-oracle testable without GPU (full run, resume, crash-preserves-paid-work). Importing the module loads no torch. Tested: `tests/scripts/test_run_rf_fusion_v1_entry.py`, `tests/scripts/test_rf_fusion_v1_launch_gate.py`, `tests/scripts/test_rf_fusion_v1_null_firewall.py`. **Terminal arm**: `--preterminal-reservation <preterminal_run>/manifest.json` supplies the persisted per-protein `C_reserved`. `load_preterminal_reservation(..., config=...)` binds it to the experiment that produced it — `campaign_id` / `phase` / `split_role` / per-protein `f_cap` must match — and `reservation_content_digest` puts the manifest's CONTENT into the §4.2 resume signature. Without both, a manifest from another campaign resolved and ran perfectly well at the wrong scale (a probe ran a 30× unmatched budget to exit 0), and editing `C_reserved` in place did not invalidate a checkpoint frozen under the old value. `M_T = floor(C_reserved / S)` `M_T = floor(C_reserved / S)` is derived per protein and the shard dispatches to `run_terminal_protein`. Canary configs: `rf_fusion_v1_entry_canary.yaml` (pre-terminal) and `rf_fusion_v1_entry_canary_terminal.yaml` (terminal); both resolve under the shipped-config test. T0 (`phase: t0`) needs no `--preterminal-reservation` and writes no `generated.parquet`: it builds no parent. **Nothing has run on the cluster yet** — the local evidence is unit/contract tests and adversarial probes, not a GPU smoke.

### Tetramer Refold Gate (PLAN_TETRAMER_GATE.md)

Hard signal is geometry vs the parent WT-predicted structure (+ 1R51 crystal for Q00511); model self-confidence (ipTM / chain_pair_ipTM / inter-chain PAE / has_clash) is a cheap pre-filter; ligand-pocket distance is advisory only. **MSA is now always our LOCAL GPU ColabFold** (the deprecated Protenix login-node server path was deleted). Prediction runs out-of-env in the shared Protenix install (`/scratch/gpfs/KAIYIJIANG/tools/protenix`); metrics run in `immune-design`.

1. `scripts/build_protenix_jsons.py` — build per-design Protenix `<name>-update-msa.json` directly from a per-design ColabFold a3m (`--msa-cf`, from #2), splitting it into Protenix `pairing.a3m` (query-only, homomer self-pair) + `non_pairing.a3m` (full a3m) under `--msa-px`, and emitting a ready-list. ## Inverse Folding -- IF Improvement (PLAN_IF_IMP.md)

MapDiff-grounded DPLM inverse-folding improvement path: IPA refiner + IPA geometry sidecar, with 4-arm ablation infrastructure.

1. `scripts/train_if_imp_refiner.py` -- Train the DPLM-compatible IPA refiner on CATH batches. Uses DPLM/ESM alphabet and `[N, CA, C, O]` coordinates, converts to IPA `[N, CA, C, CB, O]`, and saves a refiner checkpoint with config.
2. `scripts/train_if_imp_sidecar.py` -- Train the DPLM-compatible IPA geometry sidecar on CATH backbones. The sidecar is wired into the GVP encoder via a residual on `feats`; objective is DPLM decoder masked-AA recovery with everything but the sidecar frozen. Saves `sidecar_last.pt` + config.
3. `scripts/run_if_imp_refiner.py` -- Generate inverse-folding designs with optional refiner and/or sidecar. Supports the 4 ablation arms (`baseline` / `refiner` / `sidecar` / `sidecar_refiner`) via `--arm`, auto-resolved from `--refiner-checkpoint` and `--sidecar-checkpoint`. `--ablation-mode` emits per-step refiner diagnostics + per-design `ablation_diagnostics.parquet`.
4. `scripts/compare_if_imp_ablation.py` -- Cross-arm ablation comparison consuming 2-4 run dirs from `run_if_imp_refiner.py --ablation-mode`. Computes the 5 PLAN-mandated indicators (refiner-selection shrinkage, fused-vs-base entropy quantile gain, sidecar effect on base entropy, combined-vs-best-single delta, compute cost per arm) into `comparison.parquet` + `comparison_summary.json`.
5. `scripts/diag_if_imp_arms.py` -- Paired-by-design 4-arm diagnostic: runs all enabled arms on the same ~200-protein CATH subset in one process with fixed seed, using `DPLMArmDiagnosticProcessor` to emit ground-truth-aware per-step records (base/refiner/fused top-1 recovery at selected positions, base-vs-refiner agreement, fusion flip rate, reparam preservation rate, draft-init recovery, base entropy mean). Outputs `per_protein_summary.parquet` + `per_step_summary.parquet` (+ optional `per_position_records.parquet` via `--emit-per-position`).

The encoder builds a per-protein backbone kNN graph, runs sparse EGNN message passing (PyG `MessagePassing`), and refines residue hidden states with dense IPA over the original `N/CA/C` rigid frames. DPLM weights stay frozen; trainable parameters are the new encoder + draft head + configured adapter layers. Default behavior of all upstream scripts is unchanged unless `--encoder-kind=geoegnn_ipa` is set.

1. `scripts/train_if_imp_encoder.py` -- Train the GeoEGNN-IPA encoder + adapter parameters on CATH backbones. Loads DPLM via `load_if_task`, swaps `task.model.encoder` for a fresh `GeoEGNNIPAEncoder`, sets `cfg.detach_encoder_feats=False`, optionally reinstalls the decoder adapter shape before freezing, and optimizes `diff_loss + lambda_aux * encoder_loss`. Saves `encoder_last.pt` (via `save_geo_encoder_checkpoint`), `run_config.yaml`, `metrics.jsonl`, `manifest.json`. Knobs include `--adapter-num-layers`, `--adapter-gated`, `--adapter-gate-init`, `--egnn-depth`, `--egnn-hidden-dim`, `--ipa-depth`, `--ipa-hidden-dim`, `--update-coors`, `--use-updated-coord-bias`, `--lambda-aux`.

16. `scripts/analysis/c0b_gate.py` — C0b GO/NO-GO gate (PLANNER_README §C0b). Joins the ESMFold `structural.parquet` (`scTM` per folded shortlist candidate) onto `c0b_candidates.parquet` by `(protein_id, facade_design_idx)` and applies a THREE-arm per-register coordination criterion (R_B = local immune, head-LME nats, lower = better; the design is folded once per protein as the structure baseline). The decisive comparison is POST-structure: fake's low-immune draws are 9 uncompensated edits that typically wreck the fold and drop below the bar, so the reconditioned true joint wins. Pure `compute_gate(candidates, structural, …)` (the verdict/GO logic is the unit-tested `signal_diag` core; this is join + aggregation glue) + thin CLI: `--candidates-parquet`, `--structural-parquet`, `--registers-parquet` (optional, adds the true-vs-fake-joint immune diagnostic), `--output` → `c0b_gate.json`, `--verdicts-output` → per-register verdicts parquet.
